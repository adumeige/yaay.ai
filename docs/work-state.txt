REACTIVE AND GRAPH APIS
- crdt/.../Commits.kt: CommitToken, CommittedBatch and ReplicaState.
- DurableReplica.states(): initial/current complete authoritative state; slow
  collectors may skip intermediate snapshots.
- DurableReplica.commits(after): retained-history replay followed by live durable
  commits, with an independent cursor per collector. Wakeups may coalesce but
  accepted batches are not dropped. Each batch carries its resolved snapshot.
  This is replayable delivery, not exactly-once external side effects.
- graph commonMain: GraphReadModel, GraphStore, GraphQuery and GraphCheckpoint.
- GraphProjection: asynchronous serialized projection, status Flow, complete
  query-result Flow, token-aware read/await, retry and rebuild.
- EmbeddedYouTrackGraph: disk database, object/type indexes, containment/reference
  edges, atomic state/checkpoint transactions and checkpoint readback validation.
- documents/.../TypedGraph.kt: typedGraphStore includes map-key references.
- CLI commands graph-state and graph-rebuild operate on an initialized replica.

IMPORTANT INVARIANTS
The CRDT journal is authoritative; the graph is disposable. Durable commits do
not wait for graph projection. Graph notifications must never authorize workflow
execution. Future workflow decisions must validate and commit against authoritative
run state. A missing graph result is not proof of authoritative deletion.

Application coroutines should run blocking replica commits and database opening
on Dispatchers.IO. Close the projector before closing its replica. Cancelling a
collector/wait does not undo a durable commit. Use caller timeouts for token waits.

GRAPH DEPENDENCY AND RECOVERY
Pinned embedded artifact:
io.youtrackdb:youtrackdb-embedded:0.5.0-20260924.231536-66569b2-dev-20260924.232310-1
Repository: https://central.sonatype.com/repository/maven-snapshots/
Kotlin coroutines: 1.11.0. JDK toolchain: 21.

This is a YouTrackDB development build. Process-crash tests exposed a storage
allocation error after recovery, and a transaction helper that can log a commit
failure without throwing it. The adapter verifies the stored checkpoint before
publishing success. After three consecutive failures, the projector rebuilds from
authoritative state into a fresh database generation. Explicit rebuild uses the
same staging path: close/flush, reopen/verify, atomically install CURRENT.

The graph's batched WAL flush can recover an earlier complete checkpoint after
abrupt process exit; missing projections replay from the journal. Previous/failed
generations are retained for diagnosis. With the replica stopped, its graph/
cache may be removed and reconstructed. Never delete its identity or journal as
part of graph recovery. Full-snapshot projection and linear text matching are V1
choices; large-workspace performance has not been established.
